# AGENTS.md

Guide for coding agents working in this repo. Humans are welcome too.

## What this is

言葉の森 (Kotoba no Mori): an iPhone app for studying JLPT vocabulary and kanji. It is **local only**: word lists ship in the bundle (CSV and JSON), and the learner's collection and progress live in SwiftData on the device. There is no account, backend, or sync. Don't add network calls or copy that implies them.

## Layout

| Path | What lives there |

| `Frameworks/SwiftUIApps/` | All screens, view models, routing, and the design system (`Sources/DesignSystem/`) |
| `Frameworks/DomainKit/` | Use cases and params (add, delete, fetch, progress) |

| `Frameworks/DesignKit/` | Legacy and unused: it has no `Project.swift`, so it isn't in the workspace |
| `Tuist/` | Tuist manifests helpers and the external packages (ZeroCoreKit, ZeroDesignKit, ZeroNetwork) |
| `DESIGN.md` | Design system: principles, color, type, practice-square motif, components, screens, states, copy. Read it before any UI work |

## Build and run

The Xcode projects are generated by Tuist and committed.

```sh
tuist generate --no-open          # after adding, removing, or moving any source file
xcodebuild -workspace JapaneseDictionary.xcworkspace \
  -scheme JapaneseDictionary \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

- Deployment target is iOS 18. Swift 5 language mode.
- New files are not picked up until `tuist generate` runs. SourceKit reports "Cannot find X in scope" for new files until then; trust the `xcodebuild` result, not the editor.
- Unit test targets exist per framework (`<Name>Tests`) but hold only stubs.

## Architecture

- Composition root is `AppComposer` (`Frameworks/SwiftUIApps/Sources/Presentations/Composer`). Views get view models from composer `make…` functions.
- View models are `@Observable`, expose a `state` struct, and take actions through `send(_:)`. Keep that shape.
- Domain types in SwiftUIApps (`Kotoba`, `Kanji`, `WordsProgress`) map from DataKit models. Screens render the shared `StudyEntry` presentation model.
- Navigation: `AppRouter` (from ZeroCoreKit) plus `AppNavigationStack` in `Sources/Router`. Use `router.push(.detail(...))`, `router.pop()`, `router.setRoot(...)`. Don't go back to ZeroCoreKit's `swiftUIRouterInjection`: its path binding ignores writes, which breaks the back button and swipe-back.
- Tabs are a native `TabView` driven by `AppTabsViewModel.appTab`.

## Data rules that are easy to break

- "Add next" walks `allKotobas` / `allKanjis` using the saved `kotobaIndex` / `kanjiIndex`. That list order must be deterministic, which is why it uses `stableSorted`. Don't change the sort without migrating saved indexes.
- Kanji IDs are regenerated (`UUID()`) every time the bundled JSON is parsed, so compare kanji by character, not by `id`, when matching against the bundled list.
- Deleting an item decrements progress and resets the index to that item, so it becomes the next one offered.
- Screens reload on `onAppear`. Don't reintroduce "please refresh" toasts or artificial `Task.sleep` delays.

## UI rules

- Read `DESIGN.md` first. Colors, spacing, and radii come from `Forest` (`Sources/DesignSystem/Forest.swift`); don't use raw colors or ZeroDesignKit's `DefaultColors` in new UI.
- `DESIGN.md` and `Forest.swift` must agree. Change a token in `DESIGN.md` first, then mirror it in code, and recheck contrast for any color change.
- Reuse the components in `Sources/DesignSystem/ForestComponents.swift` (`StudyRow`, `StateMessage`, `PrimaryButtonStyle`, …) before building new ones.
- Japanese headwords use Hiragino Mincho via `Font.headword` or `PracticeCells`. UI text uses system text styles so Dynamic Type works.
- Moss (`Forest.moss`) is the single accent. It goes only where `DESIGN.md`'s accent rule allows: primary action, progress fill, selected tab, active page dot, system tint.
- Every list screen needs loading, empty, and error states that name the cause and the next action (`StateMessage`).
- Verify both light and dark mode and an accessibility text size before calling UI work done.
- Don't use ZeroDesignKit's `designKitInjection()`. It shows a "no network" sheet when offline, which is wrong for an offline app.

## Code comments

Comment the why: constraints, data quirks, workarounds. Don't narrate code, echo signatures, or leave vague TODOs. One line, two at most.

## Simulator automation notes

With Xcode 27 beta selected, the bundled `axe` CLI can't send input (SimulatorKit moved). Clicking the Simulator window through macOS accessibility works for most views. Popover buttons need an accessibility press on the element.
